# 人工测试模式操作与验收

用原 `启动程序.bat` 打开主窗口。需要可连接的 ADB 设备及原网络控制权限。

## 操作

1. 等流程完全停止，选择关卡，勾选唯一新增的“人工测试模式”开关。开启时会提醒一次：**点击、滑动、网络控制和游戏重启仍真实执行**，活动缺失或判断错误可能误触。
2. 点击原“启动循环”。每到原识别位置，自动弹出本次截图；点击答案后关闭弹窗，后台从原调用处继续。普通点击、滑动、选格、换关无需确认。
3. 根据当前问题回答：

| 弹窗 | 怎么操作 | 应看到什么 |
|---|---|---|
| 页面判断 | 查看完整截图，选择活动棋盘页面、主岛，声纳浮标可见、主岛或无法判断 | 原页面进入或恢复流程继续 |
| 模板检查 | 对照截图和模板，点“找到”或“未找到” | 原有无判断分支继续，无需坐标 |
| 查找并点击按钮 | 直接在截图中点目标；找不到点“未找到” | 点选位置换算回原图坐标，原流程发送点击 |
| 等待模板、retry、上划后寻找声纳 | 同一个弹窗按原间隔自动更新截图；看到目标后点找到或直接点图，也可明确点未找到、判定超时 | 人工提交后才返回原成功或失败分支 |
| 单格判断 | 对照本发 before/after 两图与红色目标标记，点命中、未命中、未开启或无法判断本格结果 | 命中/未命中按原流程登记；其余结果进入原异常恢复 |

等待型弹窗显示“已等待X秒／参考Y秒”。计时从原等待步骤起点开始，Y沿用该调用的timeout；到点后进度条停在100%，秒数和截图继续更新，提示“已达到参考时长，仍在等待人工判断”。未看到目标时无需操作；参考时长前后均可提交“判定超时”。读条不会代答、关闭弹窗或触发重启。

操作后的固定等待保持原样，持续采图沿用各入口的截图方法与poll_interval。只有原先轮询的等待入口刷新；普通页面判断、单次模板检查和单格before/after保持静态。提交坐标使用点击时显示帧的缩放映射；未显示的中间帧不积压，提交后迟到帧丢弃。

每次等待判断保存一张最终依据原图及JSON记录到 `runtime/screenshots/manual_recognition/<会话编号>/`，记录人工答案、请求和帧编号、坐标及提交时已等待秒数。retry失败返回的诊断路径也指向这张图。该目录保存诊断依据，不提供截图回放功能。

行列编号从 1 开始，与棋盘一致。图片来自原截图流程，单格复用本发已保存的两张图片；展示标记不会写入原图。无活动时可以主动选择假定结果，程序不自动代答；日志注明人工来源。击沉仍由原策略确认。

点原“停止循环”、关闭判断弹窗或关闭主窗口，都会取消等待并走原停止路径。已接受的单格答案先完整同步棋盘、策略和计数，再响应停止。

停止后可照常使用原“开启人工干预”改盘；应用后保持停止。完全空闲后取消“人工测试模式”，自动恢复开启前的正式关卡、棋盘和策略，循环保持停止。请使用原关卡选择和人工改盘功能对照当前游戏调整，再自行启动正式循环。

## 验收例子

- **HIT 与换关**：第1关初始棋盘启动；页面检查选活动棋盘页面，模板检查按问题选择或点选位置。依次给第1行第1列、第2行第1列、第3行第1列判命中，应按原策略确认长度3的潜艇。第一次胜利模板选找到，后续胜利检查选未找到，退出活动按钮检查选找到；应切到第2关4×4棋盘，累计3发、3次HIT。
- **MISS 与恢复**：第1关初始棋盘第一发选未命中，retry截图中点选重试位置；原REJECT、重试和活动恢复继续，MISS只增加1，下一目标第1行第3列。
- **超时**：MISS后等待retry时点判定超时，应进入原重启恢复，已登记的MISS不重复计数。
- **持续刷新**：在等待型弹窗暂不回答，观察后续画面和时间文字持续更新；超过参考时长仍应保持等待，棋盘、计数和后续操作不推进。目标出现后点图或点找到，只执行一次后续流程。
- **停止与关闭**：在任一弹窗等候时停止或关闭，应解除等待、保持计数，不误触发异常重启。提交后立即停止，应完整登记这次结果。
- **普通模式**：取消开关后启动，沿用原截图与自动识别，无人工弹窗。
